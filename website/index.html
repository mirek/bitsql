02 / MAKE THE SWAP

One lighter container.

Use bitsql for local development and application CI. Start here, then run your existing suite.

Run it now

docker run --rm -p 1433:1433 \
  mirek/bitsql:0.1 --auto-create-databases

Or change your Compose service

services:
  db:
    image: mirek/bitsql:0.1
    command: ["--auto-create-databases"]
    ports: ["1433:1433"]
    environment:
      ACCEPT_EULA: "Y"
      MSSQL_SA_PASSWORD: "Your_password123"

Existing MSSQL_* environment variables are accepted and ignored. For reproducible runs, pin mirek/bitsql:0.1.28. This release publishes native-validated amd64. Other architectures require validation on their native hosts.

Keep the connection. Check the setup.

01Credentials & TLSExisting usernames and passwords work. With encryption enabled, keep trustServerCertificate: true for the built-in self-signed certificate.

02Database creation--auto-create-databases creates databases on login. Use --database app to create a named database at startup instead.

03Health checksThe image has no shell or sqlcmd. Replace SQL Server health checks with a TCP/login probe. Testcontainers users should use GenericContainer and a listening-port wait.

04Fresh state, every timeEverything lives in memory. Remove persistence volumes. Seed once, then use EXEC emulator.snapshot 'seed' and EXEC emulator.restore 'seed' for fast test isolation.

03 / NO CONTAINER REQUIRED

Meet the engine. In your browser.

The same MoonBit SQL executor, compiled to JavaScript. Queries and data stay in this tab. No account, server, or installation.

⌘ / Ctrl + Enter to run · State persists between queries
Choose an example or write a query.

Browser demo: one session, no TDS socket, HTTP integrations, or scheduled waits. Waiting requests reset the demo with a notice. Stop or a 10-second timeout also resets the database. Results display at most 200 rows per set. For client and concurrency testing, use the container.

FAITHFULNESS FIRST

Built to catch failures.

bitsql targets the SQL Server behavior that application tests depend on: SQL, result metadata, TDS, and ORM workflows. Unsupported features raise explicit Emulator: … errors instead of plausible results.

Inspect bitsql plans with emulator.explain or run one query with emulator.profile to see index access and execution choices. Explicit profiles are on demand. Native query/index diagnostics now retain execution history; Query Store captures outer statements in ALL mode. Query diagnostics ↗ · History limits ↗

This is an in-memory test database. It does not replace SQL Server’s durability, operational backups, replication, or production query optimizer. Add ORDER BY wherever row order matters, and validate your application against SQL Server before release.

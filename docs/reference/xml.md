# FOR XML and the xml data type

Rules derived from captures on SQL Server 17.0.5005 (harness corpus
`xml/*.cases.json`, generated by `harness/gen/xml.mjs`). Implementation:
`src/core/xml` (tree, parser, serializer, XQuery subset), `src/core/types/xml.mbt`
(conversions), `src/core/bind/for_xml.mbt` and `bind/xml_methods.mbt`,
`src/core/exec/for_xml.mbt` and `exec/xml_methods.mbt`,
`src/core/session/precheck_xml.mbt`, TDS in `src/core/tds/type_info.mbt` /
`value.mbt` and `session/wire.mbt`.

## Wire

- Top-level FOR XML (no TYPE): one column `XML_F52E2B61-18A1-11d1-B105-00805F49916B`
  of type **NTEXT** (0x63): max length 0x7FFFFFFE, the database collation,
  then a table name of one part, `x`. Flags 1. Rows carry text pointer
  length 16 + `dummy textptr\0\0\0`, timestamp `dummyTS\0`, a 4-byte length
  and UTF-16LE. The text is split into rows of 2033 characters (as FOR
  JSON); empty text sends no rows. DONE counts the input rows.
- FOR XML ..., TYPE at the top level: one unnamed xml column (flags 3), one
  row; no input rows is one NULL row; DONE count 1.
- xml values: TYPE_INFO 0xF1 with schema-present byte 0; values are PLP with
  unknown total length (0xFFFFFFFFFFFFFFFE), UTF-16LE, no BOM. A row with a
  NULL xml is sent as NBCROW. xml columns always have fCaseSen (0x02): flags
  3 (union), 11 (table column), 35 (computed).
- tedious cannot send xml parameters (TYPES.Xml is not implemented); bitsql
  decodes 0xF1 RPC parameters (schema collections ignored), unverified.

## FOR XML in subqueries

- The value is nvarchar(max), or xml with TYPE; NULL when the query returns
  no rows; `''` when it returns rows that produce no text (NULL-only
  columns). ROOT does not change the no-rows NULL.
- ORDER BY is allowed in the subquery. A derived table needs a column alias
  (8155); its column is flags 1, a scalar subquery 33.
- String concatenation idiom: `STUFF((SELECT ',' + x ... FOR XML PATH('')),
  1, 1, '')` keeps entities (`a&amp;b`); with `, TYPE).value('.',
  'nvarchar(max)')` they are decoded.
- FOR JSON in a subquery is nvarchar(max), NULL without rows. Nested FOR
  JSON inside FOR JSON is inlined as JSON by SQL Server (not implemented:
  bitsql escapes it as a string).

## Value formatting (all modes)

Text: `& < >` as entities, CR and control characters as `&#xHH;`, LF and
TAB literal, quotes literal. Attributes: `& < > "` as entities, CR/LF/TAB as
`&#x0D;`/`&#x0A;`/`&#x09;`, `'` literal. A whitespace-only value (without
CR) writes its last character as a reference (`' '` → `&#x20;`, `'  '` →
` &#x20;`), also in the text form. bit `1`/`0`; money 4 decimals; float
`2.500000000000000e+000`, real `1.5000000e+000`; binary base64 (PATH; RAW
needs BINARY BASE64, else 6829); dates ISO with `T`, the fraction (full
scale) only when non-zero, datetimeoffset `+hh:mm` or `Z`; uniqueidentifier
upper case; sql_variant as its base type; xml values inline.

## PATH

- Row element `row` by default; `PATH('')` omits it. ROOT / ROOT('x').
- Column names: `name` element, `a/b` nested elements, `@x` and `a/@x`
  attributes, `text()`, `data()` (space only between consecutive data()
  columns), `*` / `node()` / unnamed inline (strings escaped, xml
  unescaped), `comment()`, `processing-instruction(t)`.
- Consecutive columns share open elements: `a/b, a/c` → one `<a>`; two
  columns named `x` → `<x>ab</x>`. NULL columns are skipped entirely (they
  close nothing) unless ELEMENTS XSINIL (`<x xsi:nil="true"/>`, namespace on
  the row element, or on ROOT when given).
- Empty string → `<x></x>` in the text form, `<x/>` with TYPE.
- Compile errors: 6852 attribute after content of the same element, 6851
  xml as attribute, 6864 attribute without row element, 6850 invalid name
  ("Column"/"Row"/"ROOT name ... '<c>'(0xHHHH) is the first character at
  fault"), 6849 `//` or leading/trailing `/`, 6846 state 4 `x:y`, 6855
  XMLSCHEMA.

## RAW and AUTO

- RAW: attributes per non-NULL column (names encoded `_xHHHH_`: `my col` →
  `my_x0020_col`, `1x` → `_x0031_x`, `@z` → `_x0040_z`), xml columns as
  sub-elements after the attributes. ELEMENTS: one element per non-NULL
  column, unnamed values inline. Errors: 6809 unnamed column, 6810 repeated
  name (case-sensitive), 6864 `RAW('')` without ELEMENTS, 6829 binary.
- AUTO: one element level per table in order of first column; element name
  is the alias, else the name as written (`dbo.tt`, `#xt` → `_x0023_xt`);
  rows with equal parent values nest under one parent; a child element is
  written even when all its columns are NULL (outer join); expressions
  belong to the preceding column's table. 6800 without FROM, 6859 for
  `AUTO('x')`.
- XMLSCHEMA, XMLDATA, EXPLICIT: emulator error 50109.

## The xml type

- Parse (CAST/CONVERT from n/var/char, binary UTF-8 or UTF-16 with BOM):
  fragments allowed, declaration dropped, CDATA → text, entity and char
  references expanded, CRLF → LF, attribute whitespace normalized to
  spaces, whitespace-only text dropped unless CONVERT style 1 or
  `xml:space="preserve"`. Serialization: `<a/>` for empty elements, double
  quotes, CR as `&#x0D;`.
- Parse errors 9400–9459 "XML parsing: line L, character C, ..." (C counts
  UTF-16 units from the line start); TRY_CAST gives NULL; they end the
  batch; in an RPC request ERROR is followed directly by DONEPROC (no
  DONEINPROC, no RETURNSTATUS). DTDs 6359.
- Conversions: strings and binary → xml implicit; xml → nothing implicit
  (257 to strings, 206 to others); explicit xml → strings (6354 state 10
  when too short; char(n) pads) and binary (FF FE + UTF-16LE). xml ↔
  numbers/dates/sql_variant 529.
- Not comparable: `=` etc. with xml on both sides or IN 305, with another
  type 402; ORDER BY / GROUP BY 305; DISTINCT 421; UNION/EXCEPT/INTERSECT
  5335 (UNION ALL fine); MAX 8117; LIKE / LEN / UPPER 8116; CONCAT 257
  nvarchar; `+` 402 (8117 for xml + xml); SQL_VARIANT_PROPERTY 206.
  DATALENGTH (SQL Server's internal binary size) is an emulator error.
- sys.columns/sys.types: system_type_id 241, max_length -1;
  INFORMATION_SCHEMA lengths -1.
- These type errors are compile time: a batch `DECLARE ...; SELECT <error>`
  fails before the DECLARE runs (`precheck_xml` binds table-free
  statements of the batch up front).

## Methods

- `x.value('xquery', 'type')`, `.query`, `.exist`, `.nodes` in FROM
  (`CROSS/OUTER APPLY t.col.nodes('/a') n(c)`). Method names are
  case-sensitive (227); on non-xml 258; arguments must be string literals
  (8172); arity 174; `modify()` in SELECT 8137 (SET @x.modify: emulator).
- value(): static singleton check 2389 (`(path)[1]`, `/a[1]/b[1]/@c`,
  attributes of a singleton, functions); the type cannot be xml,
  sql_variant, text, ntext, image, timestamp or unknown (9500). The
  atomized string converts as nvarchar (245 "converting the nvarchar value
  'a' ..."); empty → NULL.
- query(): attributes at the top 2396; atomic values joined by spaces.
- nodes(): column usable only as a method target or IS NULL (493); alias
  and column list required (318). An ORDER BY key with a method call is
  never matched to the select item (hidden key → flags 1).
- XQuery subset: paths (`/`, `//`, `.`, `..`, `*`, `@x`, `@*`, text(),
  node(), comment()), predicates (positions, last(), comparisons, and/or,
  not()), parenthesized filters, arithmetic, count, sum, string, data,
  local-name, position, number, contains, starts-with, string-length,
  concat, sql:variable, sql:column. Names match only elements without a
  namespace. `name()` does not exist (2395). Numbers: integral doubles print
  as integers, zero as `0.0E0`. Namespace declarations, FLWOR, casts and
  other functions are emulator errors.

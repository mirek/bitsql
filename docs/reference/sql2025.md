# SQL Server 2025 additions

2026-10-06: `harness/corpus/sql2025/substring-optional-length.sql`, captured on
17.0.5005.3, establishes the two-argument SUBSTRING form. Omitted length reads
through the end, including trailing spaces; zero/negative starts read the whole
input. Result metadata preserves the input capacity (varchar(6) stays varchar(6)
even for a literal start of 3), with binary becoming varbinary. Explicit NULL
length and NULL start return NULL. Invalid arity raises 189, severity 15, with
"requires 2 to 3 arguments". Untyped NULL and numeric sources raise 8116.

The initial `sql2025/fuzzy.sql` capture runs with default database configuration
and rejects EDIT_DISTANCE with 195. It does not establish enabled preview
semantics. See the open [audit](../design/sql2025-audit.md).

With PREVIEW_FEATURES enabled, `sql2025/fuzzy-preview.sql` captures error 9847
for SQL_* collations and successful execution with Latin1_General_100_CI_AS.
Both configuration and collation matter when verifying these functions.

## Base64

2026-10-06: `sql2025/base64.sql` and `sql2025/base64-padding.sql` capture
encoding/decoding, metadata and error precedence. Encode accepts binary and
varbinary, decode accepts char/varchar; untyped NULL returns NULL. The optional
encode flag accepts int or bit (not tinyint/smallint/bigint, decimal, float or
strings). NULL means standard alphabet, any nonzero accepted flag means URL-safe
alphabet without padding. image/text/sql_variant arguments raise 8116.

Encode returns nullable varchar(8000), promoted to max for max inputs or declared
binary capacity above 6000. Decode returns nullable varbinary(8000), or max for
varchar(max). These capacities are independent of the actual value.

Decode accepts both alphabets, omitted/incomplete padding, nonzero discarded
bits, and spaces/tabs/CR/LF. Validation is sequential: invalid alphabet is 9803
state 20, impossible final group length is state 21, a digit where second padding
is required is state 22, and any non-whitespace after completed padding is state
23. Thus `AA=A`, `AA==!`, and `AA=!=` fail with states 22, 23 and 20 respectively.

## Bigint DATEADD

2026-10-06: the three `sql2025/dateadd-bigint*.sql` cases contain 139 captured
batches. SQL Server accepts increments beyond int from bigint, decimal and
float expressions. Inputs outside bigint raise 8115/state 2; results outside
the temporal range raise 517. Multiplication must be widened before checking
the result, and time values wrap modulo one day even at bigint extremes.

For smalldatetime, an intermediate result outside the datetime range raises
517/state 1; a result within that range but outside smalldatetime raises state
2. Negative and positive amounts, temporal scales, legacy rounding and both
ends of the datetime2/datetimeoffset range are captured.

The oracle treats -9223372036854775808 nanoseconds as a no-op for datetime2
and datetimeoffset. The adjacent value shifts normally. Time still shifts at
signed minimum. Keep this observed edge separate from the general widened
arithmetic; do not infer that every signed-minimum increment is a no-op.

## Concatenation operator

2026-10-06: `sql2025/concat-{operator,semantics,boundaries,collation}.sql`
captures `||` precedence alongside `+`, strict NULL propagation even with
CONCAT_NULL_YIELDS_NULL OFF, declared-capacity metadata, truncation (including
UTF-8 byte limits), binary values and computed columns. Strings concatenate
with numeric/date/GUID operands through character conversion; bit, xml, json,
sql_variant, legacy LOBs, two numeric operands and mixed binary/string operands
raise 402. NULL error labels remain NULL rather than int. Two fixed binary
operands return fixed binary; strings return variable-length character types.

Conflicting explicit collations raise 468/state 9. Unresolved ANSI collation
raises 457 immediately; Unicode retains an unresolved label and raises 451
when projected. CASE retains its unresolved collation even when its condition
is constant; an outer explicit COLLATE can repair the CASE. Computed-column
nullability of `||` follows the bound expression.

The focused existing CASE/collation suite passes 180/184 cases. The four
non-allowlisted failures (collation-functions #050/#052, collation-join-scopes
#006/#007) also fail with the CASE change disabled; they are separate gaps.

## Preview configuration and fuzzy matching captures

`preview-configuration.sql` captures ON/OFF, cross-session visibility, invalid
values, and transaction rejection. ALTER completes with curCmd 253. Inside a
transaction it raises 226/state 7, emits ERROR then ROLLBACK_TXN, and aborts the
batch. The rollback is observable in later batches; rejecting the statement
while retaining the transaction is incorrect.

`fuzzy-functions.sql` and `fuzzy-collation.sql` capture enabled behavior.
Adjacent transpositions affect EDIT_DISTANCE, trailing spaces are ignored,
and supplementary characters are measured as UTF-16 units. Windows linguistic
collations equate expansions such as sharp-s/ss and ae ligature/ae; BIN2 does
not. Case, accent and Turkish distinctions require collation-aware matching.
These captures establish the initial implementation requirements; extended
collation coverage remains open.

`scoped-configurations.sql` captures all 41 default configuration rows and
sql_variant base types/lengths/collations. The string settings use nvarchar(16),
and FULLTEXT_INDEX_VERSION uses smallint rather than int. Generated view
metadata comes from `catalog/view-descriptors-scoped.sql`; the generator reads
both captures. `preview-state.sql` verifies shared state across connections
and transaction count/XACT_STATE after the failed ALTER.

`fuzzy-unicode.sql` adds normalization requirements: sharp-s/ss and ae ligature/ae
expand before distance and similarity calculation, decomposed e + acute equals
precomposed e-acute and occupies one position, but U+200B is retained (unlike
ordinary linguistic comparison). Existing collation sort-key generation drops
ignorables and therefore cannot be used unchanged for fuzzy character input.

`fuzzy-algorithms.sql` contains 256 deterministic pairs with repeated characters,
transpositions and cutoffs. SQL Server's Jaro transposition count compares the
matched positions to sorted matched positions, not just their characters:
repeated equal letters still contribute if their matched positions move. The
prefix adjustment applies below the conventional 0.7 threshold as well.
EDIT_DISTANCE follows optimal string alignment (adjacent transpositions),
not unrestricted Damerau distance: CA -> ABC is 3.

`fuzzy-boundaries.sql` and `fuzzy-string-types.sql` show char/varchar and
nchar/nvarchar are each accepted, but mixing the families raises 8116 for
argument 2. Bare NULL is accepted while typed int NULL is rejected. MAX string
arguments raise 8116/state 10 with the literal combined type label
VARCHAR(MAX)/NVARCHAR(MAX). The optional limit accepts integer types including
bigint, but values outside int raise runtime 8115/state 2 after result metadata.
Negative limits are unlimited; nonnegative cutoffs return at most limit + 1.

`fuzzy-normalization.sql` captures soft-hyphen removal, presentation ligatures,
accent-order equivalence, width/case distinctions and supplementary characters
under both SC and non-SC collations. Normalization retains U+200B, removes
U+00AD, expands the ffi presentation ligature, and ignores accent ordering
within a character. Under CI_AI, slashed-o equals o. A Jaro comparison where
only one original space-trimmed operand is empty returns distance 1 even when
normalization makes both operands empty; edit distance returns 0 in that case.
Two original nonempty operands that both normalize to empty have Jaro distance 0.

`fuzzy-compatibility.sql` verifies enabled fuzzy calls at compatibility levels
100, 130, 150, 160 and 170; do not impose a compatibility-170 gate on them.
